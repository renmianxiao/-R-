# 集游 PlayShelf

一个面向作品集展示的游戏售卖网站。前端使用 React，包含商品发现、搜索筛选、愿望单、购物袋、商品详情、用户评价和个人中心；Node.js API 提供账号认证、后台管理、演示订单与科技点签到。

## 项目结构与文件职责

下文路径均相对于项目根目录 `game-shelf/`。运行数据和构建文件会随使用过程变化，部分文件或目录在首次使用对应功能后才生成。

### 后端业务文件：`server/`

| 文件 | 负责的功能 |
| --- | --- |
| `server/admin-api.mjs` | 管理接口业务，包括经营统计、商品查询与维护、字段校验、封面文件上传、订单查询、订单状态校验和修改记录。管理员身份由 `server.mjs` 在分发前校验。 |
| `server/game-store.mjs` | 商品持久化模块，从初始目录建立商品数据，提供目录读取、保存、排队更新、按在售状态过滤和单款游戏查询。 |

### 游戏目录与运行数据：`data/`

| 文件或目录 | 负责的功能 |
| --- | --- |
| `data/catalog.mjs` | 组合精选游戏、导入的游戏信息和标签，形成初始目录；用于后端首次初始化和前端加载目录前的默认数据。 |
| `data/ode-games.mjs` | 从 ODE 整理的游戏目录快照，包含名称、分类、封面等基础信息；其中价格和评分为商城演示值。 |
| `data/game-tags.mjs` | 按游戏 ID 集中维护展示标签，并导出标签映射供初始目录使用。 |
| `data/games.json` | 当前可修改的商品目录，保存后台维护后的价格、标签、简介、封面和上架状态。首次初始化后，后端以此文件为准。 |
| `data/users.json` | 用户账号数据，包括用户 ID、昵称、账号或邮箱、角色、注册时间，以及密码盐和密码哈希。 |
| `data/sessions.json` | 登录会话数据，记录令牌哈希、用户 ID 和过期时间，与浏览器登录 Cookie 配合使用。 |
| `data/orders.json` | 演示订单数据，保存订单号、联系人、商品与成交单价快照、数量、金额和处理状态。 |
| `data/reviews.json` | 用户评价数据，保存游戏 ID、用户 ID、星级、文字和创建/更新时间；首次发布评价后生成。 |
| `data/points.json` | 科技点账户数据，保存用户余额及每日签到日期、奖励和时间；首次签到后生成。 |
| `data/uploads/` | 已上传的游戏封面文件；商品目录中的 `coverUrl` 指向对应上传图片。 |

愿望单、购物袋和浏览历史保存在浏览器的 `localStorage`，没有对应的服务端 JSON 文件。愿望单和购物袋属于当前浏览器，浏览历史按登录用户 ID 区分；科技点余额和签到次数由后端保存。

已有 `data/games.json` 时，修改初始目录源码不会自动覆盖后台维护的数据。日常维护商品应通过后台商品管理页面进行。

## 本地运行

需要 Node.js 20 或更高版本。

Windows 用户可直接双击项目目录内的 `启动集游.bat`，同时启动前后端并自动打开网站。缺少依赖时会先安装；运行期间保持启动窗口打开，按 `Ctrl+C` 停止项目。若已有项目服务在运行，请先停止旧服务再双击。

在项目文件夹中打开终端，执行：

```powershell
npm.cmd install
npm.cmd run dev
```

浏览器打开 `http://127.0.0.1:5173`。开发命令会同时启动 Vite 前端和 Node.js API。

修改后端后，在运行窗口按 `Ctrl+C`，然后重新执行 `npm.cmd run dev`。PowerShell 中使用 `npm.cmd` 可避免 `npm.ps1` 执行策略限制。

## 构建与启动

```powershell
npm.cmd run build
npm.cmd run start
```

生产模式通过 `http://127.0.0.1:4174` 提供构建后的网站和 API。订单记录写入 `data/orders.json`。

## 后台管理

1. 先在商城注册一个普通账号。
2. 在项目目录运行 `npm.cmd run admin:promote -- your@example.com`，将刚注册的邮箱设为管理员。
3. 使用该账号登录后打开 `http://127.0.0.1:5173/admin`（开发模式）或 `http://127.0.0.1:4174/admin`（生产模式）。

管理员角色保存在本机 `data/users.json`；不要将该文件公开或提交到版本控制。

GitHub 仓库保存源码和初始游戏目录，本地账号、会话、商品修改、订单、评价、科技点以及上传图片由 `.gitignore` 排除。首次下载项目后，商品目录会自动初始化；需要自行注册账号，再使用上述命令设置管理员。

## 科技点与每日签到

登录后可从账户菜单或个人中心签到。同一账号每天只能领取一次，按北京时间 00:00 重置；余额和签到记录由后端保存到 `data/points.json`，刷新网页和重新登录后保留。

| 奖励 | 概率 |
| --- | --- |
| 20–40 点 | 80% |
| 1–19 点 | 8% |
| 41–50 点 | 10.9% |
| 100 点彩蛋 | 1% |
| 0 点彩蛋 | 0.1% |

各区间内的整数等概率抽取。0 点也计为当天已签到，科技点目前用于展示和积累。

## 演示范围

- 购物袋、愿望单保存在当前浏览器的本地存储中。
- 注册和登录通过 Node.js API 完成；密码使用随机盐和 `scrypt` 哈希，服务端使用 `HttpOnly`、`SameSite=Lax` Cookie 保持七天登录状态。
- 演示账号和会话分别保存在 `data/users.json`、`data/sessions.json`，文件已加入 `.gitignore`；会话文件仅保存 Cookie 令牌的哈希。
- 账号数据仅保存在本地 JSON 文件中，没有邮件验证或找回密码流程，适合作品集演示。
- 提交订单会由服务端重新计算商品金额，并生成 `demo-created` 状态的演示订单。
- 项目不接真实支付，不发放真实游戏兑换码。
- 商品封面从 Steam CDN 加载；网络不可用时会显示本地渐变封面。
